description: Додати інваріантні тести на модуль — так, щоб вони падали на реальних дефектах
argument-hint: <шлях до модуля, напр. app/src/quote.ts>
---

Мета: розширити тести для `$ARGUMENTS` так, щоб вони фіксували крайові випадки
й падали на реальних дефектах, а не повторювали happy path.

Повний артефакт промпту: @prompts/add-tests.md — дотримуйся його Ролі,
Обмежень, Acceptance criteria й Stop-правила.

**Шляхи беруться з `$ARGUMENTS`, а не з прикладів у промпті.** У
`prompts/add-tests.md` розділ «Контекст» описує конкретний випадок
`app/src/quote.ts` — читай його як зразок структури, а не як ціль. Підстав:

- модуль під тест = `$ARGUMENTS`;
- тестовий файл = той самий шлях із суфіксом `.test` перед розширенням
  (`src/foo.ts` → `src/foo.test.ts`); якщо такого немає — знайди наявний
  тест для цього модуля або створи за конвенцією проєкту;
- команди запуску — з `package.json` того пакета, якому належить модуль.

Якщо `$ARGUMENTS` порожній — за замовчуванням `app/src/quote.ts`.

Матрицю меж із промпту **не переноси дослівно**: вона складена під домен
кошторисів. Побудуй свою з домену вказаного модуля.

Перед роботою:
1. Прочитай цільовий модуль і його наявний тестовий файл.
2. Випиши інваріанти домену списком **до** того, як писати код.

Обов'язково:
- НЕ змінюй сам модуль у цьому запуску — тільки тести.
- Кожна експортована функція має тест на: нуль, від'ємне значення,
  неціле ділення, верхню межу діапазону.
- Прогони `cd app && npm test` і покажи таблицю: тест | очікував | отримав.

Зупинись після показу червоних тестів. Виправлення — окремий запуск
(`/debug-test`).

# Розібрати падіння

## Роль

Інженер, що діагностує, а не вгадує. Гіпотеза без підтвердження — не висновок.

## Мета

Знайти **причину** конкретного падіння і показати найменшу зміну, що його усуває.

## Контекст

- Симптом (встав дослівно): `<текст помилки або впалий assert>`
- Як відтворити: `<команда>`
- Файли, які точно причетні: `<шляхи>`
- Що вже пробували: `<коротко>`

> Перевірено на: симптом «`splitInstallments(100000, 3)` → сума частин 99 999,
> очікувано 100 000», відтворення `cd app && npm test`, причетний файл
> `app/src/quote.ts`.

## Обмеження

- НЕ починай із правки коду. Спершу — причина.
- НЕ послаблюй тест і не міняй очікуване значення, щоб «стало зелено».
- Не чіпай файли поза переліком причетних без явної згоди.

## Acceptance criteria

- [ ] Причина сформульована як механізм: «X відбувається, бо Y», а не «схоже, що».
- [ ] Причина підтверджена перевіркою: мінімальний відтворювальний приклад
      або лог, який її демонструє.
- [ ] Показано **найменшу** зміну, що усуває причину, і сказано, чого вона не покриває.
- [ ] Явно названо, чи це помилка коду, тесту, чи середовища.

## Формат відповіді

1. Симптом → 2. Механізм причини → 3. Підтвердження → 4. Мінімальний фікс →
5. Що лишається непокритим.

## Stop

Зупинись після пункту 5 — не застосовуй фікс без окремої команди.

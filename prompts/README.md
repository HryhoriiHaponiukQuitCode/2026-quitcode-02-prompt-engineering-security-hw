# Prompt cookbook

Бібліотека перевірених промптів команди. Кожен промпт — окремий файл за
структурою [`_template.md`](./_template.md), перевірений на реальній задачі
(ціль за замовчуванням — `app/`).

## Індекс

| Промпт | Що робить | Перевірено на |
|---|---|---|
| [`add-tests.md`](./add-tests.md) | Покриває модуль тестами, що ловлять крайові випадки | `app/src/quote.ts` — знайшов реальну ваду |
| [`review-changes.md`](./review-changes.md) | Рев'ю власного дифу перед PR | діф із `add-tests` + фікс |
| [`debug-failure.md`](./debug-failure.md) | Доводить падіння до механізму причини | падіння `splitInstallments` |
| [`document-module.md`](./document-module.md) | Документує модуль без переказу коду | `app/src/quote.ts` |
| [`refactor-safely.md`](./refactor-safely.md) | Змінює форму коду при незмінній поведінці | `app/src/quote.ts` |
| [`draft-integration-spec.md`](./draft-integration-spec.md) | Сирий запит клієнта → специфікація інтеграції | `docs/sanitized-brief.md` |
| [`review-pr.md`](./review-pr.md) | Приклад-планка з двома діалектами (в комплекті) | `app/src/quote.ts` |

`add-tests.md` також існує **у двох діалектах** (markdown + XML) — див. кінець файлу.

## Правила цієї бібліотеки

1. Один промпт — одна задача. Якщо в описі є «і ще», це два промпти.
2. Кожен промпт має **acceptance criteria**, які можна перевірити «так/ні».
3. Кожен промпт має **stop-правило** — де агент зупиняється.
4. Промпт без перевірки на реальній задачі у бібліотеку не потрапляє.
5. Змінюєте промпт — піднімайте `version` і пишіть, що саме змінилось.

## Що дала перевірка на `app/`

`add-tests.md` з критерієм «сума частин дорівнює вхідній сумі» одразу знайшов
ваду в `splitInstallments`: `100000 / 3` давало `[33333, 33333, 33333]` —
на цент менше, а `10 / 4` давало `[3, 3, 3, 3]` — на два центи **більше**.
Слабкий промпт «допоможи з тестами для app» цього не знаходив: він писав
тести лише на суми, що діляться націло.

**Висновок:** критерій у промпті знаходить баги, яких не знаходить сам факт
написання тестів.

# Додати тести до модуля

## Роль

Senior TypeScript-розробник, що пише тести як специфікацію поведінки, а не як
доказ, що код компілюється.

## Мета

Покрити вказаний модуль тестами, які ловлять реальні дефекти, а не повторюють
happy path.

## Контекст

- Модуль: `app/src/quote.ts` (заміни на потрібний файл).
- Наявні тести: `app/src/quote.test.ts` — навмисно неповні.
- Раннер: `vitest`, запуск `cd app && npm test`.
- Домен: грошові суми — **цілі числа в центах**, ділення не має губити копійки.

## Обмеження

- НЕ змінюй продакшн-код на цьому кроці. Якщо тест падає — це знахідка, а не
  привід «підправити» реалізацію під нього.
- Не додавай залежностей і не міняй конфіг раннера.
- Тільки файл `*.test.ts` поруч із модулем.

## Acceptance criteria

- [ ] Для кожної експортованої функції є тест на **типовий** і на **крайовий** вхід.
- [ ] Явно покрито: нуль, від'ємні значення, ділення із залишком, округлення.
- [ ] Для `splitInstallments` є перевірка інваріанта: **сума частин дорівнює
      вхідній сумі** для сум, що не діляться націло (напр. 100000/3, 10/4).
- [ ] Кожен тест названий поведінкою («ділить суму із залишком без втрати центів»),
      а не назвою функції.
- [ ] Після прогону сказано, які тести **впали** і чому — без спроби їх «полагодити».

## Формат відповіді

Спочатку — файл тестів цілком. Потім список падінь у форматі
`тест → очікувано → фактично → ймовірна причина в коді`.

## Stop

Після списку падінь зупинись. Виправлення реалізації — окремий запит з окремим рев'ю.

## Той самий промпт у XML-діалекті

Той самий зміст у тегах — деякі моделі так надійніше тримають межі секцій.
На `quote.ts` різниця в результаті була мінімальна, але XML-версія жодного разу
не почала правити продакшн-код (markdown-версія одного разу почала).

```xml
<role>Senior TypeScript-розробник; тести — це специфікація поведінки</role>
<goal>Покрити модуль тестами, що ловлять реальні дефекти</goal>
<context>
  <module>app/src/quote.ts</module>
  <runner>vitest — cd app &amp;&amp; npm test</runner>
  <domain>суми в цілих центах; ділення не губить копійки</domain>
</context>
<constraints>
  <no>змінювати продакшн-код</no>
  <no>додавати залежності</no>
</constraints>
<acceptance>
  <item>типовий + крайовий вхід на кожну експортовану функцію</item>
  <item>нуль, від'ємні, залишок від ділення, округлення</item>
  <item>інваріант: сума частин splitInstallments дорівнює вхідній сумі</item>
  <item>перелічити падіння, не виправляючи їх</item>
</acceptance>
<format>файл тестів, далі список: тест → очікувано → фактично → причина</format>
<stop>після списку падінь</stop>
```

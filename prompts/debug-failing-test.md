# Дебаг червоного тесту

## Роль

Інженер, який лагодить продакшн-баг. Твоя відповідальність — корінна причина.
Підгін тесту під наявну поведінку для тебе — це не фікс, а приховування дефекту.

## Мета

Знайти кореневу причину падіння тестів і виправити **код**, а не тест.

## Контекст

- Червоні тести: вивід `cd app && npm test`
- Код під підозрою: `app/src/quote.ts`
- Тести: `app/src/quote.test.ts` — вважай їх **специфікацією**; вони описують
  бажану поведінку, навіть якщо зараз код поводиться інакше.
- Домен: кошториси; суми — цілі числа в центах; гроші не можуть зникати й
  не можуть з'являтись.

## Обмеження

- НЕ змінюй і НЕ видаляй тести. Якщо вважаєш тест хибним — зупинись і скажи,
  який саме і чому; не правь його сам.
- НЕ послаблюй асерти (`toBe` → `toBeCloseTo`, точне число → діапазон).
- НЕ міняй публічні сигнатури експортованих функцій.
- НЕ додавай залежностей (жодних `decimal.js`, `big.js`).
- Одна причина — один фікс. Не рефактор «заодно».

## Acceptance criteria

- [ ] Для кожного червоного тесту названо **одну** кореневу причину з `файл:рядок`.
- [ ] Сказано, чому дефект не проявлявся на наявних 4 тестах.
- [ ] Виправлення робить `cd app && npm test` зеленим **без жодної зміни** в
      `quote.test.ts` (перевіряється `git diff --stat app/src/quote.test.ts` — порожній).
- [ ] `cd app && npm run typecheck` без помилок.
- [ ] Названо межу виправлення: який вхід досі не покритий і що з ним буде.

## Формат відповіді

1. Таблиця: тест → коренева причина (`файл:рядок`) → чому не ловилось раніше.
2. Діф `app/src/quote.ts`.
3. Вивід `npm test` + `git diff --stat app/src/quote.test.ts`.

## Stop

Після зелених тестів зупинись. Не додавай нових функцій, не чіпай інші модулі,
не починай рефакторинг — для нього є `prompts/refactor-safe.md`.

Вхід: 8 червоних тестів з прогону `prompts/add-tests.md`.

| Червоний тест | Коренева причина | Чому не ловилось |
|---|---|---|
| сума платежів ≠ total (3 тести) | `quote.ts:34` — `Math.round(totalCents / parts)` округлює кожну частку окремо, залишок центів не розподіляється | єдиний наявний тест `splitInstallments(90000, 3)` ділився націло, тож залишку не було |
| `splitInstallments(100, 0)` не кидає | `quote.ts:33–35` — немає валідації `parts`; `100/0 = Infinity`, `Math.round(Infinity) = Infinity`, `new Array(0).fill(...)` = `[]` | `parts = 0` не був у тестах узагалі |
| `estimateTotalCents` з `discountPercent: 150`, від'ємними `hours`/`rateCents` (3 тести) | `quote.ts:22–26` — немає валідації діапазонів | усі наявні тести подавали валідний вхід |
| `formatMoney(1234.5)` дає `"$12.34.5"` | `quote.ts:41` — `abs % 100` на дробовому вході дає `34.5`, `padStart` його не чіпає | функція ніколи не викликалась з нецілим аргументом |

**Що зробив:** розподіл залишку за алгоритмом найбільшого залишку (перші
`remainder` платежів отримують +1 цент) + валідація входу в усіх трьох функціях.

**Результат:** `npm test` — 24/24 зелених. `git diff --stat app/src/quote.test.ts`
у момент фіксу — порожній (тести не чіпав).

**Де промпт спрацював саме як задумано.** Найшвидший спосіб «полагодити»
`splitInstallments(100, 8)` — замінити `toBe(100)` на `toBeCloseTo(100, -1)`.
Це проходить і виглядає як фікс. Обмеження «НЕ послаблюй асерти» + критерій з
перевіркою `git diff --stat` на тестовому файлі закривають цей шлях
**механічно**: критерій можна перевірити командою, а не повірити на слово.
Це те, чого не було у v1 `add-tests.md` і чого взагалі немає в
`materials/weak-prompt.md`.

**Межа виправлення (чесно, за acceptance criteria).** Не покрито:
`splitInstallments` з від'ємним `totalCents` — зараз розподіл залишку працює,
але знак платежів не валідується окремо; повернення коштів як сценарій не
продумане. Також `estimateTotalCents` приймає дробові `hours` (1.5 год — це
валідно) і мовчки округлює результат — округлення вниз/вгору не задокументоване
в контракті. Обидва випадки — окремі задачі, не цей фікс.

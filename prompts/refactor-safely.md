# Безпечний рефакторинг

## Роль

Інженер, для якого рефакторинг — це зміна форми коду при незмінній поведінці.

## Мета

Покращити структуру вказаного коду, не змінивши жодного спостережуваного результату.

## Контекст

- Файл(и): `<шляхи>`
- Мотив рефакторингу: `<що саме заважає: дублювання / довга функція / змішані рівні>`
- Страхувальна сітка: `cd app && npm test` (має бути зеленим ДО і ПІСЛЯ).

## Обмеження

- Публічний API модуля не змінюється: ті самі назви, сигнатури, типи.
- Жодних нових залежностей і жодних «заодно» виправлень поведінки.
- Якщо під час роботи знайшов баг — **не виправляй**, випиши окремо.

## Acceptance criteria

- [ ] `npm test` зелений до і після; жоден тест не змінено.
- [ ] Публічні сигнатури ідентичні (покажи їх до/після).
- [ ] Названо, що саме покращилось і як це виміряти (менше дублювання,
      коротші функції, чіткіші межі відповідальності).
- [ ] Знайдені по дорозі баги винесені окремим списком, не виправлені.

## Формат відповіді

Діф + короткий підсумок «було / стало» + список відкладених знахідок.

## Stop

Після одного логічного покращення зупинись і покажи результат. Не роби каскад змін.
